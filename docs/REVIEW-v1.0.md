## 已确认但本次不改的既有问题

| 级别 | 问题与影响 | 修改建议 |
|---|---|---|
| P1 | 双向持仓仅检查所选方向；同合约另一方向已有外部持仓时，资金费可能被归到新卡片。隔离复现中，无卡片成交也记入该合约资金费且无告警。 | 创建及同步时检查两方向；未归属仓位存在时阻止资金费归属并提示核对，或提供明确拆分证据。 |
| P1 | 纯自动卡片 complete 仅检查核算 issues；账户数量不符仍可能返回 true 和年化。本次混合卡片另查错误与过期状态，纯自动卡片保持原行为。 | 统一完整性口径，将账户核对错误、同步失败与过期纳入；保留已知部分金额但暂停完整收益和年化。 |
| P2 | 未识别的收入类型保存后被核算静默跳过，仍可能 complete=true。 | 区分重复证据、已识别调整和未知类型；未知且可能影响收益的记录形成待核对事项。 |
| P2 | 读取卡片逐腿查询并重放全部历史，卡片/事件增加后每 10 秒轮询开销扩大。 | 按事件修订版本缓存派生结果，保留可重放性；先测真实规模再优化。 |
| P2 | 文档曾描述风控写日志，实际仅有同步及调度错误日志，未见业务风险告警日志。 | 需要日志提示时，新增按风险状态变化去重的日志，避免每轮重复输出。 |

前三项使用隔离 FakeExchange/本地账本复现，未访问真实账户。P1 项在当前版本仍存在；有双向同合约外部仓位或核对异常时，应对照平台原始记录，不依赖收益完整标记。

## Omni 限制与后续建议

- 快照只描述录入后的仓位；期间多轮交易无法由最终数量和均价恢复完整盈亏。每次交易后应及时录入，后续建议逐笔手工成交或官方 CSV 导入。
- 公共费率没有个人实际结算证明及完整历史。断网缺口无法自动恢复，后续可用官方个人导出文件对账；估算不能升级为实际到账。
- USDC/USDT 1:1 为用户选定的近似，不反映脱锚及汇兑损益。后续可增加实际换算汇率。
- Omni 清仓由用户确认，系统不能验证个人实际仓位和账户风险；界面及审计明确该边界。
- 只支持最近一次手工记录修订；更早错误需要后续带审计的修订/导入工具。
