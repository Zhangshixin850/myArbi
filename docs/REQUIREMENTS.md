# 原始需求存档

以下为原始需求，实际首期支持范围与运行方式以根目录 README.MD 为准。私人面板地址已从公开文档移除。

先进行规划和模块分解。先设计一个合适的架构，并论述实现方法等。
我想做一个v1.0 跨平台套利记账系统，要求：
1.运行在ubuntu轻量服务器上，适配平台api：Binance永续，现货，alpha；Asterdex; lighter；lighter-robinhood；omni.variational（目前个人api尚未推出，只利用公开api信息）；ondo perps；entropy.io；Arcus。
可以参考https://github.com/astro-btc/astro，以及截图exam.png。
2.对于omni，行情、公开资金费信息自动刷新，卡片上提供手动输入成交数量和开仓均价的文本框，实际资金费则通过公开信息计算得到。
3.所有平台api key、风控参数设置位于轻量服务器的.env文件上。
4.策略是双腿中性策略，一腿现货（仅Binance）或永续，另外一腿是另一个平台的永续，目的主要是套资金费率。
5.交互界面为面板的形式，每个交易对为一张卡片，当我选中特定币种的symbol以及双腿的平台后，建立起一张卡片，开始进行每1min一次的下单历史的轮询，当发现有符合这个卡片信息的新单完成记录(晚于开启卡片)时，记录这个订单（仓位）的成本、手续费、数量。同时记录双腿是否平衡（币种数量上），两腿的资金费率和新入账的资金费，以及风控（监控爆仓和自动减仓、总体杠杆率和MMR），直到开始手动平仓。最后记录平仓的价格、手续费、数量，与基线对比，以计算此次净获利。
6.第一版为了简单化，暂不使用WebSocket ，只用REST轮询。
7.卡片上显示币对，双腿的平台、数量、方向、建仓时间、费率、实际净利、年化等。
8. 同一账户、同一产品、同一合约及同一持仓方向，同时只归属一张活跃卡片。
9.请在卡片界面预留自动下单的接口，这个模块暂时不做。将来可能要实现的功能是：当我设置symbol、双腿的平台、数量、价差等后，可在两边同时市价下单，或单侧限价下单，成交后另一侧市价等方式进行开仓闭仓。
10.先打通 Binance 与 Asterdex的完整记账闭环，再逐个平台扩展。
11.代码和注释要简洁易懂，代码扁平化，减少微型辅助函数的封装。

建议采用以下架构：
后端采用模块化单体，所有平台共用一个记账核心。

|组成|建议方案|作用|
|-|-|-|

| 前端 | React + TypeScript | 卡片、历史记录、资金费明细和执行参数 |

| 后端 | FastAPI + 异步任务 | 面板接口、平台连接、同步和收益计算 |

| 平台适配器 | 官方 SDK 或直接调用官方接口 | 隔离平台差异 |

| 数据库 | SQLite，开启 WAL | 保存流水、卡片、同步进度和任务 |

| 面板更新 | REST + SSE | 用户操作通过 REST，状态变化推送到面板 |

| 部署 | Docker Compose + Caddy | Ubuntu 上运行、HTTPS、重启恢复 |
